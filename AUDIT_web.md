## Кратко

Веб-слой — самая зрелая часть проекта: чистое REST-разбиение по ресурсам, типизированный клиент, живые логи через SSE, продуманные каскады фолбэков. Но с точки зрения безопасности он написан как локальная утилита «для себя», при этом слушает `0.0.0.0` без аутентификации. В таком виде запускать его в любой сети, кроме полностью доверенной, нельзя: есть чтение произвольных файлов, обход путей и, по сути, удалённое выполнение кода через связку настроек и диагностики.

Итоговые оценки: функциональность — 8/10, безопасность — 2/10, поддерживаемость — 5/10.

## Критические проблемы безопасности

Все три усиливают друг друга: сервер поднимается на `host="0.0.0.0"` (`backend/main.py:84`, `start_web_server.bat`), аутентификации нет нигде, CORS открыт (`allow_origins=["*"]`). То есть любой в той же сети обращается ко всем эндпоинтам.

### 1. Чтение любого файла с диска (LFI) — `GET /api/media/{file_path:path}`
`serve_media` (`backend/routers/media.py`) берёт путь из URL и отдаёт `FileResponse(path)` без какой-либо привязки к корню проекта:

```python
@router.get("/media/{file_path:path}")
async def serve_media(file_path: str):
    path = Path(file_path)
    if not path.exists():
        raise HTTPException(404, "File not found")
    ...
    return FileResponse(str(path), ...)
```

Запрос `GET /api/media/C:/Users/<user>/.ssh/id_rsa` (или `/etc/passwd`) вернёт содержимое файла. Без auth и с `0.0.0.0` это чтение произвольных файлов машины по сети.
**Фикс:** резолвить путь и проверять, что он внутри `output_base`/каталога проекта: `resolved = (root / file_path).resolve(); if not resolved.is_relative_to(root): 403`.

### 2. Обход путей через `project_id`
Каждый роутер строит путь так:

```python
path = Path(project_id)
if not path.is_absolute():
    path = output_base / project_id
```

Два вектора. Абсолютный `project_id` → открыть как «проект» любой каталог на диске. Относительный с `../` → `output_base / "../../.."` выходит за пределы базы (нет `.resolve()` + проверки). Дальше `write_json`/`save_meta`/`export` пишут файлы в этот каталог и запускают ffmpeg с этим `cwd` — то есть доступна и запись, и запуск процессов в произвольном месте. Показательно, что для имён музыкальных треков обход путей закрыт (`Path(name).name` в `music.py`), а для `project_id` — нет.
**Фикс:** единый резолвер: `slugify`/`Path(project_id).name` либо `resolve()` + `is_relative_to(output_base)`, и запрет абсолютных путей.

### 3. RCE через настройки + диагностику
`PUT /api/settings` (`settings.py`) без auth пишет любые поля, включая `ffmpeg`, `whisper_cli`. `GET /api/diagnostics/ffmpeg` затем выполняет заданный путь:

```python
out = subprocess.run([resolved, "--version"], ...)   # diagnostics.py:_check_binary
```

`resolved` берётся из `settings.ffmpeg`. Значит: PUT settings → `ffmpeg = C:\путь\к\любому.exe` → GET diagnostics/ffmpeg → произвольный исполняемый файл запущен. То же значение используется при экспорте видео. Это удалённое выполнение кода на машине.
**Фикс:** не запускать пользовательские пути без валидации; как минимум — auth на настройки, белый список каталогов, запрет менять пути к бинарям через сеть.

## Высокий приоритет

### 4. Нет аутентификации, привязка к `0.0.0.0`
Даже без багов выше это открытый доступ к управлению генерацией, файлам проектов и настройкам для всей сети. Для локального инструмента корректно слушать `127.0.0.1`; если нужен доступ по сети — добавить токен/басик-аус.

### 5. Неограниченный аплоад
`upload_audio` делает `content = await file.read()` — весь файл в память, без лимита размера. Большой файл кладёт процесс (DoS). Стоит стримить в файл кусками и ограничить размер.

### 6. Утечка внутренних деталей в ответах
Повсеместный паттерн `except Exception as exc: raise HTTPException(500, str(exc))` возвращает клиенту сообщения с внутренними путями и трассами. В связке с отсутствием auth — раскрытие информации. Логировать на сервере, клиенту отдавать обобщённое сообщение.

### 7. CORS `*` + `allow_credentials=True`
Невалидная по спецификации комбинация (браузеры её отклоняют) и избыточно открытая. Для локального SPA CORS вообще не нужен (фронт отдаётся тем же сервером) — можно убрать middleware или задать конкретный origin.

## Корректность и надёжность

### 8. Серверные задачи не отменяются
`useSSE` честно отмечает: `aborted` значит клиент отписался, а «серверная задача может всё ещё выполняться». Токен отмены в `run_scene_analysis`/`run_shot_generation`/`export` не прокидывается. Пользователь ушёл со страницы — whisper/LLM/ffmpeg дожигают GPU/CPU до конца. Нужен cancellation-флаг с проверками между этапами.

### 9. Гонки по файлам проекта
Долгие задачи уходят в `loop.run_in_executor(None, ...)` (общий пул). Нет блокировки на проект: параллельные `analyze-scenes` и `generate-shots` пишут в одни и те же JSON (`write_json` неатомарен — `write_text` поверх файла) → возможна порча данных. Плюс общий пул из нескольких потоков может голодать на длинных задачах (whisper, ffmpeg). Нужен per-project lock и атомарная запись (во временный файл + `os.replace`).

### 10. SSE-состояние в памяти и по одному менеджеру на роутер
Каждый файл роутера создаёт свой `SSEManager()`, всё в оперативке. Перезапуск теряет подписки; несколько воркеров не поддерживаются; нельзя подписаться одним стримом на события всех этапов. Для одиночного локального пользователя приемлемо — но это стоит зафиксировать как осознанное ограничение, а не «дырку по невнимательности».

### 11. Четыре параллельные модели данных
`Scene`/`Shot`/`AssetCard` определены в: `core/models.py`, `backend/models/schemas.py` (Pydantic), `content_pipeline_gui.py` (dataclasses) и частично `core/project.py`. При этом Pydantic-схемы фактически **не используются в ответах** — эндпоинты возвращают сырой `dict`/`.__dict__`, значит валидации ответов и OpenAPI-типов нет. Данные постоянно круговертятся JSON → dict → `pipeline.Scene(**s)` → dict. Владельцем модели де-факто остаётся монолит. Свести к одной модели в `core/` и вернуть её из эндпоинтов.

### 12. `Model(**item)` из тела запроса
`AssetCard(**item)`, `pipeline.Scene(**s)` конструируются из клиентского JSON напрямую. Неожиданный ключ → `TypeError` → 500 вместо 400. Не инъекция, но грубая обработка ввода; при переходе на Pydantic-валидацию тела уйдёт само.

### 13. Дублирование SSE-клиента на фронте
`streamSSE` в `api/client.ts` и хук `useSSE` — две реализации парсинга стрима. Версия в `client.ts` не обрабатывает терминальные события и не чистит подписку. Оставить одну (хук) — он аккуратнее.

### 14. Копипаст сборки настроек
В `scenes.py` и `shots.py` `settings_dict` собирается рефлексией dataclass + ручной домердж ключей метаданных (`video_style`, `seg_*`, …). Добавишь поле — надо не забыть в обоих местах и в `pipeline_orch`. Нужен один метод, например `project.effective_settings()`.

### 15. `create_project` игнорирует `preset`
Запрос принимает `preset`, но `create_project(..., preset="universal")` захардкожен. Либо убрать поле из API, либо прокинуть.

### 16. `reload=True` в дефолтном запуске
`backend/main.py` при прямом запуске поднимает uvicorn с `reload=True` (dev-режим). `.bat` запускает без reload — лучше, но код по умолчанию dev.

## Упаковка и запуск

### 17. Нет манифеста зависимостей
Ни `requirements.txt`, ни `pyproject.toml`, при том что `.bat` вызывает `uv run uvicorn ...`, а `uv run` без манифеста работать не будет. Окружение не воспроизвести и, вероятно, зависит от заранее активированного `.venv` (Python 3.13). Это первый по важности инфраструктурный долг: зафиксировать зависимости (fastapi, uvicorn, pydantic, PySide6 тянется транзитивно через импорт монолита).

### 18. Веб тянет за собой десктопный монолит
Все ключевые роутеры делают `import content_pipeline_gui`, а тот содержит и tkinter-GUI. Веб-сервер импортирует GUI-модуль — лишние зависимости и риск побочных эффектов при импорте. Чистую логику стоит вынести в `core/`, чтобы бэкенд не зависел от GUI (это же снимет часть проблемы №11).

## Что сделано хорошо

Обработка терминальных событий SSE продумана: генератор рвёт соединение на `done`/`error` (в коде комментарий про фикс `ConnectionResetError`), а `useSSE` корректно различает `done`/`error`/`aborted` и чистит `AbortController` при размонтировании. Каскады фолбэков в анализе сцен логируют причину каждого отката — пользователь видит, почему деградировало качество. Обход путей для имён музыкальных треков закрыт правильно (`Path(name).name`) — то есть разработчик о векторе знает, осталось применить тот же приём к `project_id`. REST-разбиение по ресурсам чистое, фронтенд-клиент типизирован, эндпоинты диагностики — приятный UX. VRAM аккуратно освобождается между этапами (embed → chat → ComfyUI).

## Приоритеты исправления

1. Закрыть LFI в `serve_media` (№1) — привязать к корню проекта.
2. Единый безопасный резолвер `project_id` (№2) — запрет абсолютных путей и `../`.
3. Слушать `127.0.0.1` вместо `0.0.0.0` либо добавить auth (№4); убрать выполнение пользовательских бинарей из диагностики (№3).
4. Лимит и стриминг аплоада (№5); перестать возвращать `str(exc)` клиенту (№6).
5. Отмена серверных задач (№8) и per-project lock + атомарная запись (№9).
6. Зафиксировать зависимости (№17), затем свести модели к одной (№11) и вынести логику из монолита (№18).

Пункты 1–3 стоит сделать до любого запуска вне полностью доверенной локальной машины.
