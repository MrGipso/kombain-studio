# Контекстная раскадровка

Контекстный слой работает до генерации материалов. Его задача — превратить
набор отдельных визуальных идей в причинную последовательность и зафиксировать
эту последовательность для автономного движка.

## Производственный поток

1. Анализ сцен формирует смысловые интервалы.
2. Глобальный visual director видит весь фильм и назначает каждой сцене:
   сюжетную линию, тип непрерывности, устойчивые ID локаций/субъектов,
   состояние на входе, событие и состояние на выходе.
3. Покадровый план получает предыдущие кадры, карту всего фильма и глобальную
   стратегию текущей сцены.
4. Детерминированный компилятор дополняет пропущенные поля, не меняя тайминг.
5. `03_context_bible.json` атомарно фиксирует сцены, сущности, локации,
   continuity-группы и причинные состояния кадров.
6. Asset Board наследует контекст, а material plan замораживает его вместе с
   запросами провайдеров.
7. Перед отправкой в Krea/LTX детерминированный prompt compiler добавляет
   фактические описания локации/субъектов, действие, состояние и композицию.
   Скомпилированные prompts сохраняются в frozen material plan.

## Контракт кадра

Каждый новый кадр содержит:

- `purpose` — функция в монтаже;
- `continuity_mode` — `independent`, `same_location`,
  `continuous_action`, `recurring_subject` или `evidence_sequence`;
- `continuity_group_id`, `location_id`, `subject_ids`;
- `state_before`, `action`, `state_after`;
- `shot_size`, `camera_angle`, `screen_direction`;
- `reference_frame_id`;
- `transition_in`, `transition_out`, `change_from_previous`.

Старые шот-листы без этих полей продолжают открываться. Новая генерация всегда
создаёт контекстный контракт и Context Bible.

## Preflight

Перед кнопкой «Материал» движок блокирует:

- повреждённую или устаревшую Context Bible;
- неполный контекст нового кадра;
- связанный кадр без continuity-группы;
- смену режима внутри одной группы;
- смену локации внутри `same_location`/`continuous_action`;
- смену субъектов внутри `recurring_subject`/`continuous_action`;
- разрыв `state_after → state_before` внутри `continuous_action`;
- рассинхронизацию Shot → Asset Card.

Смена экранного направления слева направо на противоположное остаётся
предупреждением: это может быть ошибкой оси, но может быть и осознанным
режиссёрским приёмом.

Это preflight утверждённого плана, а не QA готовых изображений. Он не запускает
визуальную модель и не инициирует перегенерацию.

## API и интерфейс

- `GET /api/projects/{project_id}/context-bible`
- `GET /api/projects/{project_id}/shots`
- `GET /api/projects/{project_id}/materials/preflight`

Страница шот-листа показывает горизонтальную киноленту, continuity-группы,
локации/субъекты и цепочку `до → действие → после`.

## Честные границы

Структурированный план не гарантирует одинаковое лицо или интерьер сам по
себе. `reference_frame_id` уже входит в контракт и frozen material plan, но
фактическая передача canonical reference в image workflow зависит от
возможностей конкретного ComfyUI workflow. До появления reference-aware
workflow контекст предотвращает логические разрывы и управляет prompts, но
генеративный дрейф внешности всё ещё возможен.

Не следует строить длинную цепь, подавая каждый предыдущий результат в
следующий: артефакты будут накапливаться. Для повторяющегося субъекта или
локации нужен один канонический reference; предыдущий кадр следует использовать
только для настоящего непрерывного действия.
