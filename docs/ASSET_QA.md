# Архитектура проверки качества материалов (QA)

Веб-конвейер использует отказоустойчивый слой проверки качества для только что
созданных изображений и видео. Это намеренно не автономный агент рендеринга:
код проверки качества не вызывает ComfyUI, LTX, поиск по стокам и не запускает
новую попытку генерации.

## Граница принятия решений

Визуальная модель возвращает только `VisionObservations`: смысловое
соответствие, композицию, читаемость ожидаемого текста, ограниченную
уверенность и типизированные видимые замечания. Pydantic отклоняет лишние поля,
недопустимые значения enum, повторяющиеся замечания и уверенность вне диапазона
`0..1`. Модель не может вернуть `accept`, `retry`, `review` или оценку качества.

`core.asset_qa` сопоставляет наблюдения с одним из вариантов:

- `accept`
- `needs_review`
- `retry_image`
- `retry_video`

Последние два — только рекомендации. Приложение никогда не выполняет их
автоматически. Ответ, не прошедший проверку схемы, получает ровно одну попытку
исправления; второй невалидный ответ или сбой транспорта превращается в
`needs_review`.

Устаревший селектор стоковых материалов теперь тоже проверяет свою оценку
`0..1` через JSON Schema. Случайный ответ `5/10` отклоняется с безопасным
значением `0.0`, а не обрезается до ложно-идеального `1.0`.

## Детерминированные проверки

Изображения проверяются и декодируются с помощью Pillow. Видео проверяются
через FFprobe и FFmpeg на:

- наличие настоящего видеопотока, размеры, FPS и положительную длительность;
- отклонение длительности от слота кадра;
- целостность полного декодирования (`-xerror`);
- чёрные интервалы (`blackdetect`);
- застывшие интервалы (`freezedetect`).

Интервалы детекторов ограничиваются, объединяются и переводятся в долю
покрытия. Технические сбои декодирования или длительности могут привести к
рекомендации повторной попытки без обращения к LLM. Пороги застывания учитывают
маршрут генерации, поэтому намеренно статичный кадр или кадр с Ken Burns не
оценивается как динамическое i2v.

## Хранилище результатов

Отчёты только дописываются в файл `.asset_qa.json` каждого проекта. Каждый отчёт
привязан к `card_id`, типу медиа и SHA-256 именно тех байтов, которые были
проверены. API помечает отчёт устаревшим, если текущий путь на доске указывает
на другие байты. Данные изображений в Base64 никогда не сохраняются.

Эндпоинты:

- `GET /api/projects/{project}/asset-board/qa` — последний отчёт для каждой
  карточки и типа медиа;
- `POST /api/projects/{project}/asset-board/{index}/qa` — явная повторная
  проверка текущего медиа с защитой по ревизии доски и стабильности карточки.

Страница «Экспорт» включает текущие непринятые отчёты в список «Контроль
качества · слабые места». Устаревшие отчёты игнорируются.

## Режимы внедрения

`ai_frame_qa` остаётся главным переключателем. `ai_qa_mode` определяет, как
применяется детерминированная рекомендация:

- `shadow` (по умолчанию): только сохранять и показывать результаты проверки;
  никогда не менять статус карточки, её утверждение или блокировку экспорта
  Master;
- `review`: сохранять результаты и помечать непринятую карточку как
  `needs_review`; перегенерации по-прежнему нет.

Изменение настроек проверки качества не делает созданные материалы
недействительными. Начните с режима shadow, изучите распределение ложных
срабатываний и пропусков, настройте пороги политики, а затем включите режим
review.

## LM Studio и безопасность GPU

Структурированные текстовые вызовы предпочитают необязательный ограниченный по
области действия Python SDK для LM Studio (`uv sync --extra local-ai`).
OpenAI-совместимый HTTP-транспорт остаётся резервным и сейчас явно используется
для входных изображений. Оба пути применяют один и тот же контракт Pydantic.

Веб-задачи с подтипом ресурса `llm`, `comfy`, `stock` или `gpu` используют одну
общую для процесса аренду GPU/VRAM, сохраняя при этом свой подтип в истории
задач. FFmpeg остаётся независимым. Это не даёт модели 26/27B и Comfy/LTX
одновременно занимать RTX 5090 в поддерживаемом однопроцессном веб-развёртывании.

Текущая аренда локальна для процесса. Будущее развёртывание с несколькими
воркерами или хостами потребует надёжной очереди или распределённой аренды; не
обходите защиту сервера от запуска второго экземпляра.

## Оставшаяся калибровка

- Прогнать режим shadow на репрезентативном производственном корпусе и
  разметить ошибки.
- Добавлять временные наблюдения VLM по выборочным кадрам только после
  детерминированных проверок.
- Перенести нативный ввод изображений в Python SDK, когда его развёрнутая
  версия будет проверена с настроенной VLM.
- Добавить выполнение повторных попыток через очередь с одобрения пользователя
  как отдельную возможность. Рекомендации проверки качества не должны
  рекурсивно вызывать генерацию.
