# MOSS-SoundEffect v2 как SFX-провайдер (альтернатива Woosh)

[MOSS-SoundEffect v2.0](https://github.com/OpenMOSS/MOSS-TTS/tree/main/moss_soundeffect_v2)
(OpenMOSS, DiT + Flow Matching, 1.3B) — text-to-audio модель с весами под
**Apache-2.0** (коммерческое использование разрешено, в отличие от CC-BY-NC у
Woosh) и управляемой длительностью **до 30 секунд** за вызов (у Woosh-сервера
длина зашита: ~5 c).

Интеграция сделана шимом `tools/moss_sfx_server.py`: он реализует тот же
контракт, что Woosh API (`GET /ping`, `POST /generate` → FLAC), поэтому
`core/sfx.py` и весь пайплайн не меняются — переключение провайдера это смена
одного URL в настройках. Детерминированные сиды по хешу запроса сохраняются.

## Установка (один раз)

Рядом с «Комбайн Studio» (в корне проекта):

```powershell
git clone https://github.com/OpenMOSS/MOSS-TTS.git
py -3.12 -m venv MOSS-TTS\.venv
MOSS-TTS\.venv\Scripts\pip install --extra-index-url https://download.pytorch.org/whl/cu128 -e "MOSS-TTS\moss_soundeffect_v2[torch-cu128]"
MOSS-TTS\.venv\Scripts\pip install fastapi uvicorn soundfile
```

Требования: Python 3.12, CUDA GPU (bf16, порядка 7+ ГБ VRAM вместе с
Qwen3-1.7B энкодером). Окружение изолированное — с основным venv проекта и с
окружением Woosh не пересекается.

## Первый запуск

Веса скачиваются с HuggingFace один раз; лаунчер по умолчанию работает
офлайн и требует явного разрешения на загрузку:

```powershell
.\start_moss_sfx.bat --allow-download
```

Дальше — просто `.\start_moss_sfx.bat` (офлайн, fail-closed, как start_woosh).
Сервер слушает `http://127.0.0.1:8510`. Первая генерация после старта может
занять несколько минут (torch.compile); `TORCHDYNAMO_DISABLE=1` выставлен по
умолчанию, как в скриптах MOSS.

## Переключение провайдера

В настройках «Комбайн Studio» поменяйте `woosh_url` на
`http://127.0.0.1:8510`. Всё остальное (кэш клипов, «перегенерировать»,
SFX-подложка экспорта) работает без изменений. Откат — вернуть
`http://127.0.0.1:8500`.

Кэш клипов не зависит от провайдера: чтобы пересоздать уже сгенерированные
Woosh'ем звуки через MOSS, удалите соответствующие файлы в `<проект>/sfx/`
или нажмите «перегенерировать» на карточках.

## A/B-сравнение

Оба сервера запущены (Woosh на 8500, MOSS на 8510):

```powershell
.\.venv\Scripts\python.exe tools\sfx_ab_compare.py --a-name woosh --b-name moss --project <output_base>\<проект>
```

Скрипт возьмёт реальные `sfx_query` из asset board проекта (или встроенный
набор без `--project`), сгенерирует пары клипов с продакшн-сидами в
`artifacts\sfx-ab\` и напишет `report.md` со временем генерации. Слушайте
пары и сравнивайте: качество, соответствие запросу, зацикливаемость, артефакты.

## Настройка шима

Переменные окружения перед запуском `start_moss_sfx.bat`:

| Переменная          | Умолчание | Что делает                                   |
| ------------------- | --------- | -------------------------------------------- |
| `MOSS_SFX_SECONDS`  | 10        | Длина клипа (1–30 с)                         |
| `MOSS_SFX_STEPS`    | 100       | Шаги солвера; меньше = быстрее, проверяйте ушами |
| `MOSS_SFX_CFG`      | 4.0       | Classifier-free guidance                     |
| `MOSS_SFX_PORT`     | 8510      | Порт сервера                                 |
| `MOSS_SFX_MODEL_DIR`| HF repo id| Локальный каталог весов или repo id          |

Клиент также может передать `args.seconds` в `/generate` (Woosh-клиент этого
не делает; поле опциональное).

## Генерация под длину спана

Экспорт определяет провайдера автоматически по `/ping`: если сервер объявляет
`provider` (это делает шим), клипы генерируются сразу под длину звукового
спана (с шагом 5 с, максимум 30 с; кэш — `sfx_<hash>_<N>s.flac`). Швов
зацикливания в подложке при этом нет вовсе; спаны длиннее 30 с по-прежнему
докрываются loop+trim. С оригинальным Woosh поведение прежнее (фиксированная
длина + loop+trim). Ручные звуки карточек не перезаписываются.

## Известные отличия от Woosh

- Генерация заметно медленнее (100 шагов против 5 у дистиллированного
  Woosh-DFlow). Для фоновой пакетной генерации SFX это обычно приемлемо;
  при нехватке скорости уменьшайте `MOSS_SFX_STEPS`.
- Клипы длиннее (10 с против ~5 с по умолчанию) — швов зацикливания в
  SFX-подложке становится меньше.
- Сервер обрабатывает один запрос за раз (GPU-лок), очереди как у Woosh нет —
  `core/sfx.py` и так шлёт запросы последовательно.
